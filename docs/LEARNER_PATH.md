# 수강생 전체 동선

공통 완료선은 선택한 미니앱을 개인화하고 새 `.ait` 파일을 만든 뒤, 본인 토스 앱의 최신 QR에서 핵심 기능을 확인하는 것이에요. 검토 요청·승인·출시는 이 완료선과 다른 단계예요.

| 시간 | 할 일 | 통과 증거 |
| --- | --- | --- |
| 강의 전 | [준비물](PREPARE.md)과 운영체제별 점검표 완료 | Node 24, pnpm 11.9.0, Git, Codex, 콘솔, 토스 앱 준비 |
| 10:00–10:15 | 오늘의 완료선과 환경 확인 | 준비 체크포인트 |
| 10:15–10:55 | [네 유형](CHOOSE_A_STARTER.md) 중 하나 선택 | 사용자 한 명과 핵심 행동 하나 |
| 10:55–12:00 | `SERVICE_BRIEF.md` 작성, 설치·doctor·setup, 기준본 브라우저 확인 | 기획서와 작동하는 기준본 |
| 12:00–13:00 | 점심·아이디어 공유 | 반영할 개선점 한 가지 |
| 13:00–13:45 | `pnpm build:qr`, 수동 업로드, 첫 QR | 기준본이 본인 토스 앱에서 실행 |
| 13:45–15:30 | `PROMPTS.md`로 콘텐츠·이름·색상 개인화 | 브라우저에서 달라진 핵심 흐름 |
| 15:30–16:15 | `pnpm check`, 새 `.ait`, 재업로드, 두 번째 QR | 변경 결과가 최신 QR에 반영 |
| 16:15–16:40 | 결과물 공유와 개선점 확인 | 설명 가능한 핵심 가치와 개선점 |
| 16:40–17:00 | [QR 이후 다음 단계](REVIEW_NEXT_STEPS.md) 정리 | 개인별 다음 행동 |

## 선택 폴더에서 실행할 순서

1. `SERVICE_BRIEF.md`를 채워 범위를 고정해요.
2. `pnpm install`과 `pnpm doctor`를 실행해요.
3. 콘솔 appName을 준비한 뒤 `pnpm setup`을 실행해요.
4. `pnpm dev`로 기준본을 브라우저에서 확인해요.
5. `pnpm build:qr`로 첫 `.ait`를 만들고 최신 QR을 확인해요.
6. `PROMPTS.md`로 `src/content`를 개인화해요.
7. `pnpm check`와 `pnpm build:qr`를 다시 실행해요.
8. 두 번째 QR에서 변경된 핵심 기능을 끝까지 사용해요.

막히면 같은 오류에 최대 10분만 쓰고 [복구 안내](RECOVERY.md)의 마지막 통과 체크포인트로 돌아가요.
