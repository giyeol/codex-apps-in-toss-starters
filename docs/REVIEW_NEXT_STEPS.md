# QR 이후 다음 단계

수업의 공통 목표는 최신 `.ait` 파일(토스에 올리는 파일)을 올리고, 본인 토스 앱의 QR에서 핵심 기능이 되는지 확인하는 것까지예요. 검토 요청, 승인, 출시는 서로 다른 단계이고 자동으로 이어지지 않아요.

## 1. QR 테스트

- 콘솔에 마지막으로 만든 `.ait` 파일을 올려요.
- 올린 뒤에 생긴 **최신** QR인지 확인해요.
- 토스 앱 로그인, 내 작업 공간 멤버, 만 19세 이상을 확인해요.
- 핵심 기능을 처음부터 끝까지 한 번은 써 봐요.
- 고친 뒤 다시 올렸다면 새 QR에서 다시 확인해요.

공식 안내상 QR을 한 번은 확인해야 검토 요청 버튼이 켜져요. 올릴 때마다 QR이 새로 생길 수 있으니, 예전 QR을 결과 증거로 쓰지 않아요.

## 2. 검토 요청 준비

- [ ] 게임 또는 비게임에 맞는 최신 출시 가이드와 체크리스트를 직접 확인했어요.
- [ ] 앱 이름·설명·아이콘·스크린샷 등 콘솔 입력 정보를 준비했어요.
- [ ] 실제 기능과 설명이 일치하고 과장된 수익·보상 표현이 없어요.
- [ ] 공식 테스트 광고만 사용하고 실제 광고 ID는 넣지 않았어요.
- [ ] 마지막 `.ait`와 마지막 QR 테스트 결과가 같은 버전이에요.
- [ ] 개인정보·외부 API·네트워크 기능이 있다면 필요한 정책과 HTTPS 동작을 별도로 확인했어요.

준비된 수강생만 콘솔에서 검토 요청을 선택적으로 진행해요. 검토 요청은 한 번에 한 버전만 가능하고, 요청 뒤 수정이 필요하면 요청을 취소한 다음 새 번들을 올려 다시 요청해야 해요.

## 3. 승인과 출시

검토 승인은 출시 완료가 아니에요. 승인 뒤 콘솔에서 별도로 출시해야 사용자에게 공개돼요. 출시는 강의 공통 범위가 아니며, 실제 공개 전에는 최신 QR과 라이브 환경 차이를 다시 점검해요.
